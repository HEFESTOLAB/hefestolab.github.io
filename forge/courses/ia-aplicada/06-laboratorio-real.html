Caso B · HEFESTO Pre-BIM Modeler + MCP

HEFESTO Pre-BIM Modeler es desarrollado por HEFESTOLAB y se utiliza aquí como aplicación real para estudiar geometría estructurada, propiedades, herramientas e interoperabilidad. HEFESTO Full es opcional: no es necesario adquirirlo para consultar la formación.

6.1 · Aplicaciones preparadas para IA

Una aplicación utilizable por personas y agentes hace explícitos sus objetos, acciones, estados y límites. La IA no debe “adivinar” una geometría ni una operación crítica: necesita contratos claros, observaciones y validación.

6.2 · HEFESTO Pre-BIM Modeler

HEFESTO organiza modelado ligero, datos técnicos y flujos de proyecto. En este laboratorio interesa como entorno donde una acción sobre parámetros puede producir geometría e información que después deben ser revisadas por el alumno.

6.3 · JSON HEFESTO

Un formato estructurado puede describir geometría, propiedades, relaciones y metadatos de forma legible por software. Esa organización facilita validaciones e intercambio, pero el alumno debe respetar el esquema y no inventar campos o valores ausentes.

  • geometría con referencias y dimensiones coherentes;
  • propiedades con nombres, tipos y unidades explícitos;
  • información estructurada para consulta y automatización;
  • datos legibles por software y verificables por personas;
  • interoperabilidad mediante transformaciones controladas.

6.5 · Herramientas MCP

Conceptualmente, un servidor puede exponer operaciones para consultar, leer, crear, modificar o revisar. Antes de usarlas, lista las tools que expone realmente tu servidor, lee su contrato y limita la práctica a las que estén implementadas. No conviertas esta lista conceptual en una promesa funcional.

6.7 · Laboratorio guiado

Brida industrial DN100

Objetivo: comprender el flujo entre información técnica, modelo de IA, herramientas, parámetros, geometría y revisión. DN100 identifica el tamaño nominal; no inventes diámetros, espesores, taladros ni norma.

01

Fuente. Selecciona una ficha técnica válida y registra fabricante, norma, clase, revisión y unidades.

02

Extracción. Pide a la IA una tabla de parámetros con valor, unidad, página y grado de confianza. Los valores ausentes quedan marcados como pendientes.

03

Esquema. Mapea sólo los parámetros admitidos por el componente y valida tipos, nombres y unidades.

04

Herramientas. Si existe una integración MCP verificada, autoriza únicamente las tools necesarias y conserva un registro de cada acción.

05

Geometría. Construye la brida en Component Studio con operaciones y parámetros disponibles en tu versión. Detente si una operación requerida no existe.

06

Revisión. Contrasta dimensiones, ejes, taladros, volumen, material, clase IFC y propiedades contra la ficha.

07

Entrega. Conserva la fuente, la tabla, los supuestos, el componente y un informe de diferencias.

6.10 · Del componente al proyecto

Un componente deja de ser una prueba aislada cuando adquiere identidad, clasificación, unidades, propiedades, revisión y reglas de colocación dentro de un proyecto. Registra su procedencia y evita que una geometría aprobada en un caso se reutilice fuera de contexto.

6.11 · Interoperabilidad

El laboratorio conecta HEFESTO JSON con posibles flujos IFC, Revit, cantidades e información. Cada transformación necesita un mapa explícito entre objetos, propiedades, unidades y pérdidas conocidas; “exportar” no equivale a conservar toda la semántica.
