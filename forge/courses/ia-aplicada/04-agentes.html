El ciclo de un agente

Un chatbot produce una respuesta dentro de una conversación. Un agente puede, además, observar un entorno, elegir una herramienta, ejecutar una acción permitida, comprobar el efecto y corregir el plan. Su autonomía siempre está limitada por herramientas, permisos, contexto y supervisión.

Resultado
  1. Qué es un agente. Un sistema que persigue un objetivo mediante un bucle de razonamiento, herramientas, acciones y observaciones.
  2. Chatbot frente a agente. El chatbot conversa; el agente puede modificar estado externo cuando dispone de una herramienta y autorización.
  3. Tools. Operaciones delimitadas como buscar, leer un archivo, pulsar un control o ejecutar una prueba.
  4. Connectors. Conexiones con servicios externos que exponen información o acciones según la cuenta y los permisos concedidos.
  5. Permisos. La frontera de seguridad: qué puede leer, escribir, enviar, publicar o eliminar el agente.
  6. Agentes de navegador. Interpretan páginas y actúan sobre controles visibles; su compatibilidad depende del navegador, producto, versión y configuración.
  7. Coding agents. Trabajan sobre repositorios, editan archivos y ejecutan comprobaciones dentro de un alcance controlado.
  8. Codex. Ejemplo de agente orientado a tareas de software y trabajo técnico con herramientas; sus capacidades dependen del entorno habilitado.
  9. Claude Code. Ejemplo de agente para trabajo sobre código desde un entorno autorizado; verifica siempre la versión y las herramientas disponibles.
  10. Skills. Instrucciones reutilizables que describen un procedimiento, sus límites, referencias y controles de calidad.
  11. Aplicaciones Agent Ready. Aplicaciones diseñadas con semántica, estados observables e instrucciones claras para que personas y agentes compartan la misma interfaz.
  12. Tareas programadas. Ejecuciones iniciadas en un momento o frecuencia definida; necesitan condiciones de parada y gestión de errores.
  13. Automatizaciones. Procesos repetibles donde entrada, acción, resultado y excepción están claramente definidos.
  14. Supervisión humana. Revisión de planes, permisos, acciones materiales y entregables, especialmente cuando el error es costoso o irreversible.
  15. Cuándo no usar un agente. Cuando una operación directa es más segura, falta trazabilidad, los permisos son excesivos o no existe una forma fiable de comprobar el resultado.
Laboratorio · Una aplicación Agent Ready

HEFESTO IFC Drawing

Herramienta gratuitaProcesamiento local del IFCInterfaz humana + agente

IFC Drawing es una herramienta gratuita de HEFESTOLAB. Permite trabajar en el navegador con un IFC local, generar vistas técnicas, añadir anotaciones y cotas, componer planos y exportar resultados. El modelo se procesa localmente: no debe enviarse a un servicio externo.

Práctica guiada · Claude en Chrome / agente de navegador compatible

Esta práctica depende de que el alumno disponga de un navegador y un agente compatible, configurado para interactuar con la página. No cualquier versión de Claude ni cualquier agente puede controlar automáticamente IFC Drawing. Comprueba primero las capacidades, permisos y modo de operación disponibles.

01

Prepara el contexto. Abre IFC Drawing y su guía Agent Ready. Si usas un IFC real, confirma que el archivo permanece en el navegador y que puedes compartir su contenido conforme a tus reglas.

02

Define un objetivo acotado. Por ejemplo: inspeccionar la interfaz, proponer una secuencia para preparar una vista y detenerse antes de exportar.

03

Entrega instrucciones. Indica que debe usar la misma interfaz visible que una persona, observar el estado después de cada acción y no asumir que un clic ha funcionado.

04

Autoriza por etapas. Permite primero navegación y lectura; después, una acción reversible. Para nuevas proyecciones o capturas 3D se necesita un IFC real.

05

Revisa visualmente. Comprueba modo activo, vista, escala, selección, anotaciones y composición. Corrige el plan si el estado visible no coincide con el esperado.

06

Exporta sólo el resultado revisado. PDF, SVG o DXF son opciones existentes, pero el alumno debe decidir el formato y validar el archivo final.

El aprendizaje no es que “la IA hace planos sola”, sino que una interfaz legible, unas instrucciones versionadas, observaciones de estado y revisión humana permiten a un agente participar en un flujo gráfico, no únicamente textual.

Qué debes poder explicar

  • la diferencia entre una instrucción y una Skill reutilizable;
  • por qué interpretar el estado visible es parte del ciclo del agente;
  • qué permisos fueron necesarios y cuáles no;
  • dónde intervino el criterio humano;
  • por qué la compatibilidad del agente no puede darse por supuesta.
