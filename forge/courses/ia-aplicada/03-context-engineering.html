Bloque 03 · Context engineering

El contexto es parte del sistema

El trabajo profesional con IA no consiste en encontrar una frase mágica, sino en construir un entorno de decisión.

Del prompt aislado al sistema

El prompt sigue siendo importante, pero una frase no contiene por sí sola el proyecto, sus restricciones, sus fuentes ni sus criterios de aceptación. Context engineering organiza todo lo que el modelo necesita ver, las herramientas que puede usar y la forma de comprobar el resultado.

Resultado profesional
  1. Objetivo. Expresa qué decisión o entregable debe producirse y para quién.
  2. Contexto. Incluye antecedentes, estado actual, vocabulario del proyecto y relaciones necesarias.
  3. Restricciones. Delimita alcance, normativa, formatos, acciones prohibidas, seguridad y plazos.
  4. Datos. Aporta valores, unidades, versiones y una indicación clara de qué fuente es autoritativa.
  5. Ejemplos. Enseñan el patrón esperado; deben ser representativos y no contradecir las reglas.
  6. Formato de salida. Define secciones, tabla, JSON, longitud, idioma o esquema de nombres antes de generar.
  7. Iteración. Divide el trabajo en propuesta, comprobación y refinado. No intentes resolver una cadena larga con una única instrucción.
  8. Documentos. Identifica versión, páginas relevantes y orden de prioridad. La mera carga de un archivo no garantiza que todo su contenido sea usado.
  9. Imágenes. Aclara qué debe observarse y qué no puede inferirse: escala, orientación, fecha y relación con otros datos.
  10. Datos estructurados. Tablas, CSV, JSON o esquemas reducen ambigüedad cuando la estructura es estable y válida.
  11. Fuentes. Distingue la evidencia primaria, la referencia secundaria y el texto producido por el propio modelo.
  12. Verificación. Convierte el criterio de calidad en comprobaciones observables: totales, unidades, enlaces, tolerancias y casos límite.
  13. Instrucciones reutilizables. Una guía versionada, Skill o plantilla captura reglas recurrentes y evita reconstruir el contexto desde cero.

Ejemplos técnicos breves

Ejemplo · Mediciones

De “revisa estas cantidades” a una comprobación reproducible

Adjunta la tabla, define la unidad de cada columna, indica qué partidas se excluyen, aporta el total de control y exige una salida con diferencias, hipótesis y fila de origen. El resultado ya puede auditarse.

Ejemplo · IFC

De “analiza el IFC” a una pregunta concreta

Explica el objetivo —por ejemplo, revisar espacios para un modelo analítico—, aporta la versión IFC, define los campos relevantes, prohíbe inventar propiedades ausentes y solicita un informe que separe hechos, inferencias e incidencias.

Práctica

Construye un paquete de contexto

Selecciona una tarea técnica habitual. Prepara una página con objetivo, contexto mínimo, restricciones, datos, dos ejemplos, formato de salida y cinco comprobaciones. Pide primero un plan y no el resultado final. Revisa qué información faltaba antes de continuar.
