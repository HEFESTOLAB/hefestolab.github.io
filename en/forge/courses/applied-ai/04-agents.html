The agent cycle

A chatbot produces an answer within a conversation. An agent can also observe an environment, choose a tool, execute an authorised action, inspect the effect and correct its plan. Its autonomy is always bounded by tools, permissions, context and oversight.

  1. What an agent is. A system that pursues an objective through a loop of reasoning, tools, actions and observations.
  2. Chatbot versus agent. The chatbot converses; the agent may change external state when it has a tool and authorisation.
  3. Tools. Bounded operations such as searching, reading a file, pressing a control or running a test.
  4. Connectors. Connections to external services that expose information or actions according to the account and permissions granted.
  5. Permissions. The security boundary defining what the agent may read, write, send, publish or delete.
  6. Browser agents. They interpret pages and operate visible controls; compatibility depends on browser, product, version and configuration.
  7. Coding agents. They work on repositories, edit files and run checks within a controlled scope.
  8. Codex. An example of an agent for software and technical work with tools; its capabilities depend on the enabled environment.
  9. Claude Code. An example of an agent for authorised code work; always verify the available version and tools.
  10. Skills. Reusable instructions that describe a procedure, its limits, references and quality controls.
  11. Agent Ready applications. Applications with semantics, observable state and clear instructions so people and agents can share the same interface.
  12. Scheduled tasks. Runs triggered at a defined time or frequency; they need stop conditions and error handling.
  13. Automation. Repeatable processes with clearly defined input, action, result and exceptions.
  14. Human oversight. Review plans, permissions, material actions and deliverables, especially where error is costly or irreversible.
  15. When not to use an agent. When a direct operation is safer, traceability is missing, permissions are excessive or the result cannot be checked reliably.

Guided practice · Claude in Chrome / compatible browser agent

This practice requires a compatible browser and agent, configured to interact with the page. Not every Claude version or browser agent can automatically control IFC Drawing. First check the capabilities, permissions and operating mode available to you.

01

Prepare the context. Open IFC Drawing and its Agent Ready guide. If you use a real IFC, confirm the file remains in the browser and that its use complies with your data rules.

02

Set a bounded objective. For example, inspect the interface, propose a sequence for preparing a view and stop before export.

03

Provide instructions. Require the same visible interface that a person uses, observable state after every action and no assumption that a click succeeded.

04

Authorise in stages. Allow navigation and reading first, then one reversible action. A real IFC is required for new projections or 3D captures.

05

Review visually. Check active mode, view, scale, selection, annotations and composition. Correct the plan if visible state differs from expectations.

06

Export only the reviewed result. PDF, SVG and DXF are available options, but the learner chooses the format and validates the final file.

The lesson is not that “AI makes drawings by itself”. It is that a legible interface, versioned instructions, observable state and human review allow an agent to participate in a graphical workflow, not only a text workflow.
