Case B · HEFESTO Pre-BIM Modeler + MCP

HEFESTO Pre-BIM Modeler is developed by HEFESTOLAB and is used here as a real application for studying structured geometry, properties, tools and interoperability. HEFESTO Full is optional: purchasing it is not required to access the training.

6.1 · AI-ready applications

An application usable by people and agents makes its objects, actions, states and limits explicit. AI should not “guess” geometry or a critical operation; it needs clear contracts, observations and validation.

6.2 · HEFESTO Pre-BIM Modeler

HEFESTO organises lightweight modelling, technical data and project workflows. In this lab it provides an environment where a parameter action can produce geometry and information that the learner must then review.

6.3 · HEFESTO JSON

A structured format can describe geometry, properties, relationships and metadata in software-readable form. This supports validation and exchange, but the learner must respect the schema and never invent missing fields or values.

  • geometry with coherent references and dimensions;
  • properties with explicit names, types and units;
  • structured information for querying and automation;
  • software-readable data that people can verify;
  • interoperability through controlled transformations.

6.5 · MCP tools

Conceptually, a server may expose operations to query, read, create, modify or review. Before using them, list the tools actually exposed by your server, read their contracts and limit the lab to implemented capabilities. Do not turn this conceptual list into a product promise.

6.7 · Guided lab

DN100 industrial flange

Objective: understand the flow between technical information, AI model, tools, parameters, geometry and review. DN100 identifies nominal size; do not invent diameters, thicknesses, holes or a standard.

01

Source. Select a valid technical datasheet and record manufacturer, standard, class, revision and units.

02

Extraction. Ask AI for a parameter table with value, unit, page and confidence. Mark absent values as pending.

03

Schema. Map only supported component parameters and validate types, names and units.

04

Tools. If a verified MCP integration exists, authorise only the necessary tools and retain a record of each action.

05

Geometry. Build the flange in Component Studio with operations and parameters available in your version. Stop if a required operation does not exist.

06

Review. Check dimensions, axes, holes, volume, material, IFC class and properties against the datasheet.

07

Deliver. Retain the source, table, assumptions, component and a differences report.

6.10 · From component to project

A component becomes more than an isolated test when it has identity, classification, units, properties, revision and placement rules inside a project. Record provenance and avoid reusing approved geometry outside its context.

6.11 · Interoperability

The lab connects HEFESTO JSON with possible IFC, Revit, quantity and information workflows. Every transformation needs an explicit map between objects, properties, units and known losses; “export” does not mean preserving all semantics.
