Block 03 · Context engineering

Context is part of the system

Professional AI work is not about finding a magic phrase; it is about building a decision environment.

Review priority: mediumReviewed: 20 AUG 2026

From an isolated prompt to a system

The prompt still matters, but one sentence cannot contain a whole project, its constraints, sources and acceptance criteria. Context engineering organises everything the model needs to see, the tools it may use and the method for checking the result.

Professional result
  1. Objective. State which decision or deliverable must be produced, and for whom.
  2. Context. Include background, current state, project vocabulary and required relationships.
  3. Constraints. Bound scope, standards, formats, prohibited actions, security and deadlines.
  4. Data. Provide values, units, versions and a clear indication of the authoritative source.
  5. Examples. Demonstrate the expected pattern; make them representative and consistent with the rules.
  6. Output format. Define sections, table, JSON, length, language or naming scheme before generation.
  7. Iteration. Split work into proposal, check and refinement rather than resolving a long chain in one instruction.
  8. Documents. Identify the version, relevant pages and priority. Uploading a file does not guarantee that all its content is used.
  9. Images. Explain what must be observed and what cannot be inferred: scale, orientation, date and relationship to other data.
  10. Structured data. Tables, CSV, JSON and schemas reduce ambiguity when the structure is stable and valid.
  11. Sources. Separate primary evidence, secondary reference material and the model's own generated text.
  12. Verification. Turn quality into observable checks: totals, units, links, tolerances and edge cases.
  13. Reusable instructions. A versioned guide, Skill or template captures recurring rules instead of rebuilding context from scratch.

Short technical examples

Example · Quantities

From “review these quantities” to a reproducible check

Attach the table, define each column's unit, identify excluded items, provide a control total and require an output with differences, assumptions and source rows. The result is now auditable.

Example · IFC

From “analyse the IFC” to a precise question

Explain the objective — for example, reviewing spaces for an analytical model — provide the IFC version, define relevant fields, prohibit invented missing properties and request a report that separates facts, inferences and findings.

Practice

Build a context package

Choose a regular technical task. Prepare one page with the objective, minimum context, constraints, data, two examples, output format and five checks. Ask for a plan before the final output, then review what information was missing.
