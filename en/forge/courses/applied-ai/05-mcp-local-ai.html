Connect AI to real tools

Part A · MCP

Model Context Protocol provides a common way to expose tools and context to AI applications. It does not replace the application, grant permissions by itself or automatically turn any software into an agent.

Application
  1. The problem MCP addresses. It reduces bespoke integrations between every AI client and each data source or tool.
  2. Client. The application that connects to servers and presents their capabilities to a model or user.
  3. Server. The component that publishes bounded capabilities and translates requests to a real system.
  4. Tools. Invocable actions with an input and output contract, such as query, create or validate.
  5. Resources. Addressable information that the client can read as context without necessarily treating it as an action.
  6. Prompts. Reusable templates or workflows offered by a server; they do not replace user judgement.
  7. Context. Conversation data, resources, results and constraints around each invocation.
  8. Permissions. The server should expose only what is needed; the client and user decide what is authorised.
  9. Local MCP. Client and server may run on the same computer with processes and files under local control.
  10. Remote MCP. The connection crosses a network and requires authentication, encryption, access control and trust in the service.
  11. Security. Validate inputs, keep secrets out of context, log material actions and enforce least privilege.
  12. What MCP is NOT. It is not a model, database, autonomous agent, complete permission system or guarantee of functional compatibility.

Part B · Local AI

Local AI means inference runs on hardware under your control. It can improve privacy and autonomy, but does not remove the need for correct licences, security, verification and sufficient resources.

  1. What local AI means. The model and inference engine run on your computer or private infrastructure.
  2. LM Studio. An example application for discovering, downloading and running compatible models locally; always review the selected model's requirements and licence.
  3. Open models. “Open” may refer to weights, code or licence: read the specific conditions of use.
  4. RAM. System memory available to the model, context and other applications.
  5. VRAM. GPU memory, which may accelerate inference when engine and model are compatible.
  6. Quantisation. Reduces numerical precision to lower memory and improve speed, with a possible quality trade-off.
  7. Context. Long windows consume more memory and time; size them to the need, not the theoretical maximum.
  8. Privacy. Local execution reduces transfers to the model provider, while files, logs, extensions and connected servers still require control.
  9. Performance. Depends on model, quantisation, CPU/GPU, memory, context length and inference software.
  10. Cloud versus local. Cloud offers managed infrastructure; local offers control. Neither dominates every case.
  11. Hybrid architecture. Combines local and cloud models and tools according to sensitivity, quality and cost.

Part C · RAG

Retrieval-Augmented Generation retrieves relevant fragments from a collection and adds them to context before generation. It is useful where information is extensive, reused and needs traceable search.

  1. What RAG is. A pattern separating information retrieval from answer generation.
  2. Embeddings. Numerical representations used to estimate semantic similarity; they are not a human-readable copy of the document.
  3. Retrieval. Selecting fragments through search, filters or similarity before passing them to the model.
  4. When to use RAG. Large, recurring, versioned collections or shared use cases where retrieval can be measured and maintained.
  5. When direct context is enough. For a few documents or one-off work, providing the relevant information directly may be simpler and more reliable than deploying RAG.

Three distinct concepts

MCP connects capabilities; local AI defines where the model runs; RAG defines how information is retrieved. They can combine, but none automatically implies the others.

Practice

Draw a minimal architecture

For a confidential collection of technical datasheets, decide what stays local, what could use cloud, whether direct context is enough or RAG is needed, which actions an MCP server would expose and which authorisations each tool requires.
